Finding (full docs dump, 2026-10-03 evening; supersedes the earlier "static headers only" note): GoClaw MCP servers support `require_user_credentials` with per-user credential overrides (`mcp_user_credentials`, PUT /v1/mcp/servers/{id}/user-credentials?user_id=). Credential user is resolved by `resolveCredentialUserID()`: in group chats it tries the individual sender first (via `channel_contacts.user_id`), then falls back to the group contact `group:{channel}:{chatId}`. Docs say "numeric sender ID" (Telegram-centric); behaviour for Lark `ou_` open_ids is unverified. PreToolUse HTTP hooks can return `updatedInput` (stock) — a possible attestation injection path if the hook payload carries session/sender (payload fields undocumented). Group messages carry only a `[From: name]` text annotation — never trust it as actor.
