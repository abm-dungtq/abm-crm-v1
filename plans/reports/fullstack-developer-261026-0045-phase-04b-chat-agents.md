## Bridge null `conversationId` finding (override a)

The bridge accepts it. In `apps/zalo-bridge/src/crm-client.ts:26` the claimed-command schema has `conversationId: z.string().nullable()`. In `command-runner.ts:192-200`, `dispatch` uses `conversationId` only as an optional queue key (`key ? this.queues.get(key) … : Promise.resolve()`), so a null id just runs without per-conversation ordering. The `run_completion` handler (`completionPayload`, lines 28-34) needs only `agentKey`, `userId` and `text`. zod drops the extra chat fields, and `completionText` returns the text as-is when there is no `zaloUserId`. The `chat-agents.test.ts` test asserts `conversation_id IS NULL` on the queued command.
