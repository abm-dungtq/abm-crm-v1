```
set DEMO_EXPORT=1&& pnpm exec vitest run test/demo-learner-generate.test.ts -u
```

Do not run `generate-demo-seed.mjs` without `--demo-eval`. That rewrites `demo.sql`.

`toMatchFileSnapshot('../seed/learner-demo.sql')` with `-u` wrote the host file. The export test takes `new Date()` once, floors it to the minute, then starts fake timers. That value is both the timeline anchor and `-- generated-at`. A guard still throws if the anchor is behind the last timeline step. The other generator test still pins the clock at `2026-08-01T03:04:05.000Z` and does not use the anchor.

This export's UTC day was still 2026-10-07, so story dates kept the same day offset as the previous file (first contact `2026-08-12`, partner contracts `2026-08-01` / `2027-08-01`). A later UTC day moves those dates with the stamp.

## Freshness

B2B working-hour dates and the learner timeline are both anchored at generation time. First-contact SLA is 4 working hours, so `STALE_AFTER_MS` is 60 minutes. The comparison is `now - stamp > 60 minutes`: exactly 60 minutes is still fresh, 61 minutes is stale. A missing stamp is stale.

`--check` and `--apply` refuse a stale sample. A dry run warns. `--allow-stale` is dry-run only: pairing it with `--check` or `--apply` refuses even when the sample is fresh. The refusal text is `Sample SQL is older than 60 minutes` plus the two regenerate commands.

## Map

JSON shape:

```json
{
  "organizationId": "org-abm",
  "department": "dep-kd",
  "teams": { "kd1": "team-kd1", "kd2": "team-kd2" },
  "users": {
    "slot-admin-1": "",
    "slot-sale-1": "",
    "slot-sale-2": "",
    "slot-sale-3": "",
    "slot-leader-1": "",
    "slot-leader-2": "",
    "slot-head-1": "",
    "slot-academic-1": "",
    "slot-teacher-1": "",
    "slot-teacher-2": "",
    "slot-accountant-1": ""
  }
}
```

`slot-sale-1` and `slot-leader-1` must sit on `teams.kd1`. `slot-sale-2`, `slot-sale-3`, and `slot-leader-2` must sit on `teams.kd2`. That matches the live eval roster: one sale on kd1, two sales on kd2. Lead `team_id` is copied from the owner at creation. Contact and task have no `team_id` column. Queue leads with no owner keep a null team.

`slot-teacher-1` and `slot-teacher-2` accept role `teacher` or `admin` and must be two different users. `slot-head-1` accepts role `head` or `admin`. A head is checked against `department`; an admin in that slot skips the department check. Admin, academic, teacher, and accountant must have `organization_id` equal to `organizationId`. Two sale or leader slots mapped to the same user id are rejected. `slot-admin-1` may be the same user as `slot-head-1` or a teacher slot.

The seed test still inserts teacher slots as role `teacher`. It does not prove teacher-only class lists for an admin standing in that slot. `myClasses` limits the list to assigned classes only when `actor.role === 'teacher'`. That source behavior was left unchanged.

## Backup

`--apply` requires `--backup-file` outside the repo. Before any remote write the loader prints:

`--backup-file contains all staff emails and session rows and must be kept private`

It refuses to overwrite an existing file. After the export it prints the `wrangler d1 time-travel info abm-crm-eval` bookmark, checks emptiness again, then applies. Time Travel was not run in this session.

## Cleanup and reload

Cleanup does not delete `outbox` or `idempotency_key`. Payload free text is not a delete key: an approval or idempotency row can mention a demo id after staff use the app, and `audit_log` is matched on `entity_id` only. Deleting those rows by a substring would contradict that rule.

The loader emptiness check therefore ignores `outbox`, `idempotency_key`, and `audit_log` rows that are not demo data. Every business table must still be empty. A demo `audit_log` row (`id` or `entity_id` like `demo-%`) still blocks the load. `lead_counter` must be one row with `next_value` 1, and `fee_counter` must have no row.

Cleanup still recomputes counters from remaining rows. `lead_counter.next_value` becomes one past the highest remaining `L-[0-9]*` code, or 1 when no lead remains. `fee_counter` is deleted when no charge remains; otherwise it becomes one past the highest remaining `HP[0-9]*` code. Staff, team, department, organization, session, and agent-token rows are not deleted.

Post-apply counts still include `audit_log`, `outbox`, and `idempotency_key`. Those counts are printed; they do not block the load.

## Phones
